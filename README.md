## 初始化数据库

两步：先建表，再灌种子数据。

```bash
# 第 1 步：建库建表（meeting_room 库 + user / meeting_room / reservation 三张表）
mysql -u root -p < database/01_schema.sql

# 第 2 步：灌入演示数据（默认账号 + 会议室 + 已占用时段）
mysql -u root -p < database/02_seed.sql
```

第二步执行完会打印三张表的记录数、**默认账号一览**与**今日占用时段一览**；看到 `admin`、`user1` 即成功。

三张表与第 5 周 DFD 数据存储的对应：`user` → **D1 用户信息**、`meeting_room` → **D2 会议室信息**、`reservation` → **D3 预约记录**。

> ⚠️ 两个脚本均可重复执行，但**有破坏性**：`01_schema.sql` 删表重建、`02_seed.sql` 清空后重灌，仅影响这三张表，请勿在有真实数据时执行。
> 种子数据的预约日期由 `CURDATE()` 动态生成，因此**任何一天执行，查询页都能看到"今天"的占用时段**。

**实测状态**：✅ 已通过（2026-10-12）——两条命令在 MySQL 8.0.46 上一次执行成功、零报错：建表后按序输出三张表（`meeting_room`=D2、`reservation`=D3、`user`=D1），种子数据输出「3 用户 / 4 会议室 / 5 预约」+ 默认账号一览 + 今日占用时段一览。
> 约束实测：唯一键、6 组 CHECK、外键全部真实生效——6 次越界插入（重名账号、结束早于开始、跨天、超 8 小时、非法角色、预约不存在的会议室）**无一例外被数据库拒绝**，且不留残余数据。证据见「实测记录」。

## 常见问题

1. **端口被占用（8080 / 5173）**：改 `backend/src/main/resources/application.yml` 的 `server.port`；前端 `npm run dev -- --port 5174`。查占用：Windows `netstat -ano | findstr 8080`。
2. **`Access denied for user 'root'@'localhost'`**：密码不对。按"启动后端"一节设 `DB_PASSWORD` 环境变量，或直接改 `application.yml`。
3. **`Public Key Retrieval is not allowed`**：MySQL 8 默认认证插件所致。本项目 JDBC URL 已带 `allowPublicKeyRetrieval=true`；若你自行改过 URL，请补回该参数。
4. **时间差 8 小时 / 中文变问号**：JDBC URL 必须保留 `characterEncoding=utf8&serverTimezone=Asia/Shanghai`。
5. **★ 为什么 `09:00-10:00` 与 `10:00-11:00` 不算冲突？** 预约时间采用**半开区间 `[start, end)`**——含开始时刻、不含结束时刻。前一条的 `end` 恰好等于后一条的 `start`，两者首尾相接、并无重叠，因此**不判为冲突**（FR-09 / UC-U03 业务规则）。种子数据中 A101 今日就刻意放了这样一对，供验收时现场核对。
6. **`mvn` 报"无效的目标发行版"或依赖下载极慢**：确认 `JAVA_HOME` 指向 JDK 17；下载慢可在 `~/.m2/settings.xml` 配置阿里云镜像。
7. **`java` 可用但 `javac` 不可用**：装的是 JRE 而非 JDK，重装 JDK 17。
8. **★ 启动后端口不是 8080**：先查环境变量——若系统里存在 `SERVER_PORT` 或 `SERVER__PORT`，Spring Boot 的宽松绑定会把它当成 `server.port`，**优先级高于 `application.yml`**。查：Windows PowerShell `Get-ChildItem Env: | Where-Object Name -like "*PORT*"`；清：`Remove-Item Env:SERVER__PORT`（本机实测就撞上了这条，详见「实测记录」）。

### 六、实测暴露并已修复的问题

1. **不存在的接口返回 500（应为 404）**——Spring Boot 3.2 对未匹配路径抛 `NoResourceFoundException`，原代码只有兜底的 `Exception` 处理器，把它一并报成 500，前端无法区分"接口写错"与"后端崩了"。
   **修复**：`GlobalExceptionHandler` 增加 `NoResourceFoundException → 404`、`HttpRequestMethodNotSupportedException → 400`；复测通过。

## 5. 第 3 周成果：可行性分析与方案决策

### 5.1 两个备选方案

- **方案 A：自由时间段预约** —— 用户自定义预约开始与结束时间，系统通过区间重叠检测判断冲突。
- **方案 B：固定时段预约** —— 系统预设可预约时段，用户从中选择空闲时段，天然无冲突，无需冲突检测。

### 5.2 比较与决策

13 项维度、5 分制评分（满分 65）：**方案 A 得 51 分，方案 B 得 54 分**。

方案 B 虽在实现容易度类维度（实现难度、工作量、库表设计、冲突处理）占优，但失分点——无法自定义时长、后续扩展需重构——恰好命中核心诉求。方案 A 在功能完整性、闭环完整性、后续扩展能力上优势明显，其难点（区间重叠检测、并发控制）算法成熟、技术可控。

> **最终决策：采用方案 A（自由时间段预约）作为 V1.0 实施方案。**

### 5.3 已识别的主要风险与对策

| 风险 | 对策 |
|------|------|
| 并发预约冲突导致数据不一致 | 数据库事务 + 行锁（乐观锁／悲观锁） |
| 时间边界情况（跨天、零时长等） | 前后端双重校验：开始时间须晚于当前时间、结束时间须晚于开始时间、单次不超过 8 小时、禁止跨天 |
| 冲突检测算法正确性 | 单元测试覆盖重叠／相邻／包含／跨天边界；核心逻辑两人交叉审查 |
| 用户遇冲突后挫败 | 冲突时展示该会议室当日占用时段，便于用户另选时段（不做推荐算法） |

## 6. V1.0 范围基线

### 6.1 最低运行闭环

- **普通用户**：登录 → 查询会议室 → 提交预约 → 系统检测时间冲突 → 预约成功 → 查看／修改／取消我的预约
- **管理员**：登录 → 管理用户 → 管理会议室 → 查看和处理预约
- **系统**：能够启动、连接数据库、保存预约数据，并完成一次可演示的完整流程

### 6.2 本学期必须实现（12 项）

1. 用户登录和角色区分　2. 会议室信息管理　3. 会议室查询　4. 预约申请
5. 时间冲突检测　6. 我的预约查看、修改和取消　7. 管理员管理用户

11. 基本测试　12. 系统能够启动和演示

### 6.3 本学期暂不实现（9 项）

人脸识别、物联网设备控制、3D 会议室场景、智能推荐、重复预约／周期预约、多级审批、消息推送、与学校统一身份认证系统对接、移动端原生应用。

### 6.4 核心业务规则

- **冲突检测**：新预约 `[start_new, end_new)` 与已有预约 `[start_old, end_old)`，当 `start_new < end_old` 且 `end_new > start_old` 时判为冲突；首尾相接（`end_new == start_old` 或 `start_new == end_old`）不算冲突。
- **唯一性**：同一会议室同一时段只允许一条有效预约。
- **可修改性**：距会议开始超过 30 分钟才可修改或取消；已开始的预约不允许修改或取消。
- **时长限制**：单次预约不超过 8 小时，禁止跨天。

## 三、常见问题（FAQ）

### A. 启动与环境

  **Q1：换一台机器就起不来？**
按顺序检查前置依赖：`java -version` 必须是 17，`node -v` 必须是 20.x，MySQL 必须是 8.0.x。Spring Boot 3.2.x 在 JDK 17 以下会直接报类文件版本不兼容。

  **Q2：为什么不做成 Docker 一键启动？**
本组验收环境为同学 Windows 本机，容器化需额外安装 Docker Desktop / WSL2 并联网拉镜像，与验收标准"不增加安装负担"直接冲突，故选择本机直接运行，前后端各一条命令启动。

  **Q3：前端页面显示错乱、按钮点不到？**
确认使用 Chrome / Edge 近两个主要版本，分辨率在 1366×768 ~ 1920×1080 之间。

  **Q4：MySQL 连接报错（时区 / 字符集 / public key retrieval）？**
使用 MySQL 8.0.x，建库建表用 `utf8mb4` 字符集；连接串按需补 `serverTimezone=Asia/Shanghai` 与 `allowPublicKeyRetrieval=true`。

### B. 登录与权限

  **Q5：登录后进不了管理页面 / 看不到管理菜单？**
这是**预期行为**：系统按账号角色提供功能，普通用户不显示用户管理、会议室管理和全部预约入口（FR-02）。请使用管理员账号登录。

  **Q6：操作一会儿就被踢回登录页？**
会话令牌有有效期，过期强制退出属设计要求（NF-04），重新登录即可。若管理员已停用你的账号，则需管理员重新启用后才能登录。

### C. 会议室与预约

  **Q7：明明没人的会议室，提交预约却被拒绝？**
冲突判定按**半开区间 `[start, end)`** 比较，判定条件为 `start_new < end_old 且 end_new > start_old`。部分重叠、完全重叠都会拒绝；**首尾相接不算冲突**——已有 09:00—10:00 预约时，08:00—09:00 与 10:00—11:00 均可提交（FR-09 / FR-10）。

  **Q8：查到的会议室列表里找不到某间？**
该会议室可能已被管理员**停用**：停用后已有预约仍可查，但**不作为新的预约选项**，普通用户不能为其提交新预约（FR-04 / FR-06）。管理员重新设为可用后即可预约。

  **Q9：提交预约被拒绝，提示时间不合规？**
单次预约须满足：结束时间晚于开始时间、**不跨天**、**不超过 8 小时**（FR-08）。另外会议主题、参会人数、联系人、起止时间均为**必填**，缺项会被拒绝并提示补充（FR-07）。

  **Q10：为什么"我的预约"改不了 / 取消不了？**
只有**距会议开始超过 30 分钟**的本人未开始预约才能修改或取消；已进入会议中或距开始 30 分钟内的预约一律拒绝（FR-12 / FR-13，三处口径已在 V1.1 统一）。

  **Q11：取消预约后时段能立刻被别人抢走吗？**
能。用户取消或管理员强制取消后，预约状态更新为已取消、**会议室时段立即释放**，可被其他用户再次预约，状态与数据库保持一致、无脏数据（FR-13、NF-08）。

  **Q12：多人同时抢同一间同一时段，会不会重复占用？**
不会。数据库事务保证高并发下**同一会议室同一时间段仅生成一条有效预约**，其余请求做兜底拦截并提示冲突（FR-09、NF-07）。

  **Q13：提交失败后填的内容全没了？**
该体验问题（P01）对应 FR-18「预约失败后保留已填信息」，属"**有时间再完成**"的增强项；V1.1 基线未交付时，请在提交前先复制长文本，或重新填写后再次提交。

### D. 管理员操作

  **Q14：删除会议室提示"请先处理预约"？**
存在有效预约的会议室不允许删除，需先处理完相关预约（FR-03）。新增时若**同楼栋 + 同房间号**已存在，会被拒绝并提示会议室已存在。

  **Q15：管理员强制取消预约被拒绝？**
强制取消**必须填写取消原因**，未填写会被拒绝并提示（FR-16）。

  **Q16：管理员的敏感操作有痕迹吗？**
有。新增/停用用户、新增/删除会议室、强制取消预约、角色变更等操作会完整记录操作人账号、操作时间、操作类型与变更前后数据；日志普通用户不可见，且不能被业务界面删除（NF-14）。
