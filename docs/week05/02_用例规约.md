## UC-U01 普通用户登录

角色：普通用户

前置：系统可访问，用户进入登录页面。

主流程：输入账号和密码并提交 → 系统验证账号、密码、账号状态和角色 → 验证通过 → 建立登录状态，进入普通用户页面并提示登录成功。

异常：账号不存在、密码错误或账号被停用 → 拒绝登录并提示原因；普通用户尝试访问管理功能 → 拒绝访问，不授予管理权限。

后置：成功时用户可查询会议室并管理本人预约，页面不显示管理入口；失败时不建立有效登录状态。

## UC-U03 提交预约

角色：普通用户

前置：普通用户已登录，并选定会议室。

主流程：填写会议主题、参会人数、联系人、开始时间和结束时间并提交 → 系统检查必填信息、会议室状态和预约时间规则 → 检测同一会议室的时间冲突 → 检查通过 → 写入预约记录并返回预约编号，提示预约成功（直接成功，无审批步骤）。

异常：必填信息不完整、会议室已停用、开始时间不晚于当前时间、结束时间不晚于开始时间、跨天或超过 8 小时 → 拒绝提交并说明原因；时间冲突 → 拒绝提交并提示已占用时段，不生成第二条有效预约（半开区间 `[start, end)`，当 `start_new < end_old` 且 `end_new > start_old` 时判定冲突，首尾相接不算冲突）。

后置：成功时新增一条已确认的预约，占用对应时段，可在“我的预约”中查看；失败时不新增预约。

## UC-U04 查看／修改我的预约

角色：普通用户

前置：普通用户已登录；执行修改时，已有本人尚未开始且有效的预约。

主流程：进入“我的预约” → 系统显示本人历史和未来预约的会议室、时间段、主题和状态 → 选择记录查看详情（仅查看时结束） → 修改符合条件的预约的会议室或时间段并提交 → 系统检查归属、状态、会议室可用性及时间规则，重新检测冲突（排除原记录自身） → 检查通过 → 更新原预约和占用时段，提示修改成功。

异常：本人没有预约 → 显示暂无预约；尝试查看或修改他人预约 → 拒绝访问；预约已开始、已取消、目标会议室不可用、新时间不符合规则或发生冲突 → 拒绝修改并提示原因，原预约保持不变。

后置：查看不改变数据；修改成功时更新原预约，不额外生成预约，原占用与新占用同步调整。

## UC-U05 取消我的预约

角色：普通用户

前置：普通用户已登录，已有本人尚未开始且有效的预约。

主流程：进入“我的预约”并选择记录 → 提交取消请求 → 系统检查预约归属、状态及是否已开始 → 检查通过 → 将状态更新为已取消，释放占用时段并提示成功。

异常：尝试取消他人预约 → 拒绝操作；预约已经开始 → 拒绝取消并说明原因；预约已经取消 → 提示当前状态，不重复处理。

后置：成功时保留已取消的历史记录并释放原占用时段，会议室可用且满足预约规则时可再次预约该时段；失败时原预约保持不变。

## UC-A03 管理会议室

角色：管理员

前置：管理员已登录；修改、删除或调整状态时，已选定一个会议室。

主流程：进入会议室管理页面并选择新增、修改、删除、启用或停用 → 新增或修改时填写名称、楼栋和房间号、容量、用途及状态，系统检查信息完整性和位置唯一性；删除时检查有效预约并由管理员确认；启用或停用时更新状态，停用后禁止新预约并保留已有预约 → 保存操作结果，刷新列表并提示成功。

异常：信息不完整或楼栋和房间号与其他会议室重复 → 拒绝保存并说明原因；删除的会议室存在有效预约 → 拒绝删除并提示先处理预约；普通用户尝试管理会议室 → 拒绝访问。

后置：会议室信息和状态按操作更新；删除成功后从列表移除；停用后仍可显示为不可用，但不能作为新预约选项。

## UC-A04 查看和处理预约

角色：管理员

前置：管理员已登录。

主流程：进入全部预约页面 → 系统显示各用户预约记录 → 选择记录查看详情和状态（仅查看时结束） → 对需要取消的异常预约进入“UC-A05 强制取消异常预约” → 处理完成后返回列表，显示更新后的预约状态。

异常：系统没有预约记录 → 提示暂无预约；普通用户尝试查看全部预约 → 拒绝访问；取消操作未完成或被拒绝 → 显示原因，预约状态不因进入处理页面而改变。

后置：查看不改变预约；完成取消处理时，结果与第 4 周“UC-A05 强制取消异常预约”的后置条件一致。
