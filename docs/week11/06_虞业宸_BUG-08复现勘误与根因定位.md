# BUG-08 复现勘误与根因定位（虞业宸，2026-11-09）

## 结论（TL;DR）

**BUG-08「375×667 手机视口下登录页横向溢出」为复现工具伪影，页面本身无缺陷。**
用 CDP 设备模拟固定 375px 布局视口后实测：`scrollWidth = 375`，**零溢出、零超宽元素**；
320px（iPhone SE 级别）同样通过。建议改判「复现方法缺陷」并**关闭** BUG-08，
TC-10 的 375×667 结论相应改判**通过**（1366×768 原本就通过）。

## 原复现为什么是错的

原复现命令（`01_测试报告.md` BUG-08 条目）：

```
msedge --headless=new --force-device-scale-factor=1 --window-size=375,667 --screenshot=... http://localhost:5173/login
```

问题在 `--window-size=375,667`：**Windows 对窗口有最小宽度限制**，Edge headless
（headless=new）拿不到 375px 的真实窗口，实际布局视口是 **492px**；`--screenshot`
输出的图片尺寸却是 375×667 —— 相当于把一张按 492px 排版渲染的页面**裁掉右边 117px**。
卡片在 492px 里居中（左侧留白 56px），裁剪后看起来就像「卡片右侧被切、文字被裁」。

### 定位过程

1. 在登录页临时注入测量层（`?bug08` 参数触发，定位后已还原），把所有超宽元素的
   `getBoundingClientRect()` 画到页面顶部，用原命令截图读取，得到决定性证据：

   ```
   scrollWidth=492 innerW=492   ← innerWidth 是 492，不是命令行给的 375！
   html/body/#app/... w=492
   div.el-card.login-card w=380 right=436   ← 卡片只是"在 492 里居中"，并非元凶
   ```

   证据截图：`screenshots/bug08-measure-overlay-492.png`

2. 改用 puppeteer-core 驱动本机 Edge，`page.setViewport({ width: 375, height: 667 })`
   ——CDP 设备模拟**强制布局视口等于 375**，不受窗口最小宽度影响，拿到地面真相：

   | 视口 | innerWidth | scrollWidth | 溢出 | 超宽元素 |
   |---|---|---|---|---|
   | 375×667 | 375 | **375** | 无 | 0 个 |
   | 320×667 | 320 | **320** | 无 | 0 个 |

   证据截图：`screenshots/bug08-emu-375.png`（卡片完整，「第 4 组」正常换行无裁剪）、
   `screenshots/bug08-emu-320.png`；原始 JSON：`evidence/bug08_375_report.json`、
   `evidence/bug08_320_report.json`。

3. 对照：原命令产物（布局 492 被裁成 375 的假象）保留在
   `screenshots/bug08-headless-window-cropped.png`，可与 `bug08-emu-375.png` 直观对比。
