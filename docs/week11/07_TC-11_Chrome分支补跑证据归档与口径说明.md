## 2. 被测对象（决定证据效力边界）

执行入口是分册工程的 `scripts/week11/compat.mjs`（日志开头 `meetingroom-week11-sunruopu@1.1.0`），该脚本用 `playwright-core` 驱动本机已安装的 Edge／Chrome，并由 `startMock` 启动**本地 mock 服务**提供接口数据，没有连接组仓的 Spring Boot 后端与 MySQL。截图中的会议室数据（「学术报告厅」「图书馆B1」等 6 间）与组仓 `database/02_seed.sql` 的种子数据（逸夫楼 A101／A202、图书馆 B301 报告厅）不是同一套；页脚「V1.0 · 第 11 周测试与修复」与「V1.0 · 核心闭环」只存在于分册前端，组仓 `frontend/src/` 零命中。

因此本批证据的被测对象是**分册前端 + 本地 mock**，与《测试报告》§1.4 已确立的口径一致：分册与组仓「不是同一次测试、不是同一份代码，不构成矛盾，也不互相替代」。

## 3. 能关闭什么

**ENV-11-01（分册执行机未安装 Chrome）→ 已关闭。** 该缺口的定义是「分册执行机只有 Edge，Chrome 三个常见安装路径均不存在，TC-11 的 Chrome 分支无法执行」，其登记时就写明「补装 Chrome 后重跑同一脚本即可，无需改代码」。本次正是补装 Chrome 后按同一脚本复跑，Chrome 三视口与 Chrome 全流程均通过，环境缺口已实际消除，且不计产品缺陷。关闭依据已同步《测试报告》附录该条、§3 统计表与缺陷关闭确认表。
