## 2. 快速启动（三步，每步一条命令）

### 2.1 完整系统（合并到组仓库后）

> 本目录没有 `backend/` 与 `docs/week07-08/schema.sql`，下面三步用于**组仓库最终形态**；只跑本前端见 §2.2。
>
> 环境准备（不计入三步）：安装 Node ≥ 20、JDK 17、Maven 3.9+、MySQL ≥ 8.0.16，并在 `frontend/` 执行一次 `npm ci` 安装前端依赖。

```bash
# 第 1 步：初始化数据库（建库 + 建表 + 约束 + 索引 + 初始数据，一个文件一次执行）
mysql -u root -p --mysqlx=0 < docs/week07-08/schema.sql

# 第 2 步：启动后端（JDK 17）
mvn -f backend/pom.xml spring-boot:run

# 第 3 步：启动前端
npm --prefix frontend run dev
```

说明：

- `schema.sql` 是自包含的，第 1 步**不需要**再跑 `database/` 下的拆分文件。
- `--mysqlx=0` 避免 MySQL X Protocol 端口与已有实例冲突。
- MySQL 必须 **≥ 8.0.16**，否则 CHECK 约束不生效。
- 默认账号见 §3；口令不入库明文、不进配置文件默认值。

### 2.2 本目录（只有前端 + mock）

```bash
# 第 1 步：安装前端依赖（使用 lockfile）
npm run setup

# 第 2 步：同时启动 mock 与 Vite（内部两个进程，一条命令）
npm run dev
```

浏览器打开 `http://localhost:5173`。

> 想分开两个终端：`npm run dev:mock`（8080）＋ `npm run dev:web`（5173）。
> 需要跑 smoke/e2e/week11 脚本时，先在根目录执行一次 `npm install` 安装 `playwright-core`。

## 4. 页面与路由（V1.0）

| 路由 | 页面 | 可访问角色 | 说明 |
|------|------|-----------|------|
| `/login` | 登录页 | 未登录 | 账号/口令登录；账号不存在与口令错误同一句提示；无注册/忘记密码 |
| `/rooms` | 会议室列表 | 普通用户、管理员 | 按名称/最小容量/位置筛选；显示可预约/已停用 |
| `/rooms/:id` | 会议室详情 | 普通用户、管理员 | 基本信息复用列表接口；按日期查已占用/空闲时段 |
| `/bookings/new` | 提交预约 | 普通用户 | 行内校验；冲突时展示占用时段并保留已填内容 |
| `/bookings/mine` | 我的预约 | 普通用户 | 四态展示；距开始超过 30 分钟可修改/取消；取消后释放时段 |
| `/admin/bookings` | 全部预约处理 | 管理员 | 按会议室/日期筛选；强制取消必须填写原因 |
| `/admin/rooms` | 会议室管理 | 管理员 | 新增/编辑/启停/删除；存在有效预约时删除返回 409 |
| `/admin/users` | 用户管理 | 管理员 | 创建、修改姓名/部门/角色、启停；当前账号自我保护 |
| `/admin/logs` | 操作日志 | 管理员 | 只读；操作人/时间/类型/对象/摘要/变更前后数据 |
| `/403` | 无权访问 | 已登录 | 角色不匹配时跳转 |

角色规则：

- 普通用户菜单：会议室查询、我的预约；不渲染管理入口。
- 管理员菜单：会议室查询 + 4 个管理入口；不渲染“我的预约”（权限矩阵取舍，管理员处理预约走“全部预约处理”）。
- 管理员不能提交个人预约：前端路由限制 + mock 返回 403；正式后端必须同样校验。
- **前端路由守卫不是安全边界**：普通用户直接调管理接口必须由后端返回 403（NF-03）。

## 5. 现场验收路径

### 5.1 普通用户八步

| 步 | 操作 | 预期 |
|----|------|------|
| 1 | user001 登录 | 进入会议室列表；菜单只有“会议室查询 / 我的预约” |
| 2 | 按名称或容量筛一次 | 条数与内容对得上（如 `301` → 3号楼301） |
| 3 | 进学术报告厅详情，选“明天” | 看到种子占用 10:00–11:00 与其余空闲时段 |
| 4 | 提交 11:00–12:00 | 成功并给出 `MRyyyyMMddNNNN` 预约号 |
| 5 | 再提交 10:30–11:30 | 409，提示“该时段已被占用”，列出 10:00–11:00，已填内容保留 |
| 6 | 打开“我的预约” | 看到第 4 步记录，状态“待开始”，有修改/取消按钮 |
| 7 | 修改为 12:00–13:00 | 保存成功，列表时间同步 |
| 8 | 取消这条，回详情 | 状态“已取消”；12:00–13:00 重新出现在空闲时段 |

### 5.2 管理员四步

| 步 | 操作 | 预期 |
|----|------|------|
| 1 | admin001 登录 | 菜单含 4 个管理入口、无“我的预约”；访问 `/bookings/mine` 被 403 拦截 |
| 2 | 全部预约处理，按会议室 + 日期筛选 | 条数与内容对得上（如 3号楼301 + 明天 → 课题组周会） |
| 3 | 强制取消一条已结束异常预约 | 不填原因前端拒绝；填写后成功；状态变“已取消” |
| 4 | 打开操作日志 | 可查强制取消/新增会议室/修改会议室/删除会议室/新增用户/修改用户/角色变更；可展开变更前后 JSON |

### 5.3 30 分钟口径

修改与取消按钮只对“待开始且距开始超过 30 分钟”的预约展示；不足 30 分钟时按钮禁用并提示，后端还会再校验一次（FR-12／FR-13）。演示时挑明天的预约。

## 8. 常见问题（FAQ）

**Q1：`npm ci` 报 lockfile 不一致 / Node 版本过低？**
用 Node ≥ 20，确认在 `frontend/` 下执行；不要在 `frontend/package.json` 里用 `^`／`~`，否则会重新解析版本。

**Q2：8080 或 5173 被占用？**
mock 用 `MOCK_PORT=18080 npm run dev:mock`；Vite 用 `npm run dev:web -- --port 5199 --strictPort`；同时把 `VITE_PROXY_TARGET` 指到 mock 端口。

**Q3：Element Plus 装成了 2.14？**
说明用了 `^2.7.8`。本项目锁定 `2.7.8`，先删 `node_modules` 与 lockfile 再 `npm ci`，不要用 `npm install` 升级。

**Q4：MySQL 版本要求？**
必须 **≥ 8.0.16**；低于该版本 CHECK 约束会被静默忽略。连接时加 `--mysqlx=0`，避免 X Protocol 端口冲突。

**Q5：375px 下表格要横向滑？**
是预期行为：`.table` 最小宽度 720px，在 `.table-wrap` 内滚动，页面本身不横向溢出。卡片式移动布局留到第 12 周。

**Q6：没有 Chrome 能做兼容测试吗？**
不能互相替代。本机只实测 Edge 156；安装 Chrome 后重跑 `npm run test:week11:compat`，脚本会自动检测并补齐 Chrome 分支。

**Q7：mock 重启后数据/令牌没了？**
mock 数据在内存，重启即重置；令牌也在内存，重启后旧令牌失效。正式后端不存在这个问题。

**Q8：前端已经拦住了管理入口，后端还要校验吗？**
要。前端路由守卫不是安全边界；普通用户直接调管理接口必须由后端返回 403（NF-03）。mock 已按此实现，正式后端必须同样校验。

**Q9：管理员为什么没有“我的预约”？**
按角色说明的权限矩阵，管理员处理预约走“全部预约处理”。若组内决定调整，先改角色说明/需求清单，再改 `RoleMenu.vue` 与路由。

**Q10：演示口令在哪里？**
正式后端：BCrypt 入库，测试口令由部署环境注入；mock：启动日志打印本次随机口令。仓库与截图都不出现明文口令。
