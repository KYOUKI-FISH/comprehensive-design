# 第 10 周前端接口假设

本文记录第 10 周前端页面依赖的接口契约。前端以本文为准实现；正式后端由李知渔、虞业宸按第 8 周《02_数据库与接口设计.md》落地。若正式后端字段不同，**先改本文与 `frontend/src/types/api.ts`，再改 `api/*.ts` 适配，不要把兼容逻辑散落到页面**。

## 1. 通用约定

| 项 | 约定 |
|----|------|
| Base URL | `/api`（开发环境由 Vite 代理到后端；可用 `VITE_API_BASE_URL` 覆盖） |
| 认证 | `Authorization: Bearer <token>` |
| 请求体 | `application/json` |
| 成功响应 | HTTP 200，`{ "code": 0, "message": "...", "data": ... }` |
| 失败响应 | HTTP 4xx/5xx，`{ "code": 业务码, "message": "中文业务提示", "data": ... }` |
| 时间格式 | 本地时间字符串 `YYYY-MM-DDTHH:mm:ss`（不带时区后缀），日期 `YYYY-MM-DD` |
| 令牌有效期 | 30 分钟；登录响应可带 `expiresIn`（秒），前端以服务端为准 |
| 401 | 前端清除本地会话并跳转 `/login?reason=expired` |
| 403 | 前端展示中文“无权执行该操作”，不跳页（路由层另有 403 页） |

## 2. 第 9 周已有接口（本周不改）

### 2.1 登录

`POST /api/auth/login`

```json
// 请求
{ "username": "user001", "password": "******" }
// 成功 data
{ "token": "...", "expiresIn": 1800, "user": { "id": 1, "username": "user001", "name": "张同学", "department": "计算机学院", "role": "USER", "status": "ACTIVE" } }
```

- 账号不存在与口令错误统一返回 `401 +「账号或密码错误」`，防账号枚举。
- 停用账号返回 `403 +「账号已停用...」`。

### 2.2 登出

`POST /api/auth/logout`，成功 `data: null`；旧令牌立即失效。

### 2.3 会议室列表

`GET /api/rooms?name=&location=&minCapacity=`

```json
// data
[
  { "id": 1, "name": "学术报告厅", "location": "图书馆B1", "capacity": 120, "equipment": ["投影仪", "音响"], "status": "AVAILABLE" }
]
```

- `equipment` 允许数组或字符串，前端统一格式化展示。
- 筛选条件为空时返回全部。

### 2.4 占用时段

`GET /api/rooms/{id}/occupancy?date=YYYY-MM-DD`

```json
// data
{
  "roomId": 1,
  "roomName": "学术报告厅",
  "date": "2026-10-29",
  "occupiedSlots": [{ "startTime": "2026-10-29T10:00:00", "endTime": "2026-10-29T11:00:00" }],
  "freeSlots": [{ "startTime": "2026-10-29T08:00:00", "endTime": "2026-10-29T10:00:00" }]
}
```

- `freeSlots` 允许合并为跨多个小时的整段（前端按区间判断覆盖关系，不假设按小时切分）。
- 日期非法返回 `400`。

### 2.5 提交预约

`POST /api/bookings`

```json
// 请求
{ "roomId": 1, "subject": "课题组周会", "attendees": 10, "contact": "张同学", "startTime": "2026-10-29T11:00:00", "endTime": "2026-10-29T12:00:00" }
// 成功 data
{ "id": 5, "reservationNo": "MR202610290005", "roomId": 1, "roomName": "学术报告厅", "subject": "课题组周会", "attendees": 10, "contact": "张同学", "startTime": "2026-10-29T11:00:00", "endTime": "2026-10-29T12:00:00", "status": "PENDING", "createdAt": "2026-10-28T16:00:00" }
```

冲突（`409`）：

```json
{
  "code": 40901,
  "message": "该时段已被占用，请选择其他时间",
  "data": {
    "occupiedSlots": [{ "startTime": "2026-10-29T10:00:00", "endTime": "2026-10-29T11:00:00" }]
  }
}
```

## 3. 第 10 周新增接口

### 3.1 我的预约

`GET /api/bookings/mine`（仅 `USER`）

```json
// data: BookingVO[]
[
  {
    "id": 5,
    "reservationNo": "MR202610290005",
    "roomId": 1,
    "roomName": "学术报告厅",
    "subject": "课题组周会",
    "attendees": 10,
    "contact": "张同学",
    "startTime": "2026-10-29T11:00:00",
    "endTime": "2026-10-29T12:00:00",
    "status": "PENDING",
    "createdAt": "2026-10-28T16:00:00"
  }
]
```

取消后额外字段：

```json
{ "status": "CANCELLED", "cancelReason": "用户主动取消", "cancelledBy": "user001", "cancelledAt": "2026-10-28T16:10:00" }
```

**状态四态由后端推导，前端不计算：**

| 条件 | status |
|------|--------|
| 已取消标记 | `CANCELLED` |
| 当前时间 < 开始时间 | `PENDING` |
| 开始时间 ≤ 当前时间 < 结束时间 | `ONGOING` |
| 当前时间 ≥ 结束时间 | `FINISHED` |

建议排序：`PENDING` → `ONGOING` → `FINISHED` → `CANCELLED`，同组按开始时间倒序。

### 3.2 修改我的预约

`PUT /api/bookings/{id}`（仅 `USER`，仅本人）

```json
// 请求（roomId 可选，不传沿用原会议室）
{ "subject": "课题组周会（改期）", "attendees": 10, "contact": "张同学", "startTime": "2026-10-29T12:00:00", "endTime": "2026-10-29T13:00:00" }
// 成功 data: BookingVO（修改后）
```

拒绝规则（均为 `400` 或 `409`，中文提示）：

- 已取消 → `该预约已取消，无法修改预约`
- 非 `PENDING` → `会议已开始或已结束，无法修改预约`
- 距开始 ≤ 30 分钟 → `距会议开始不足 30 分钟，无法修改预约`
- 改后时段冲突 → `409 + data.occupiedSlots`
- 他人预约 → `403 +「无权操作他人的预约」`

### 3.3 取消我的预约

`DELETE /api/bookings/{id}`（仅 `USER`，仅本人）

- 成功 `data` 为取消后的 `BookingVO`（`status=CANCELLED`）。
- 拒绝规则同 3.2，动作名替换为“取消预约”。
- 取消后该时段立即释放，占用时段接口不再返回。

### 3.4 全部预约（管理员）

`GET /api/admin/bookings?roomId=&date=`（仅 `ADMIN`）

```json
// data: AdminBookingVO[]
[
  {
    "id": 2,
    "reservationNo": "MR202610290002",
    "roomId": 2,
    "roomName": "3号楼301",
    "userId": 1,
    "username": "user001",
    "userName": "张同学",
    "department": "计算机学院",
    "subject": "课题组周会",
    "attendees": 12,
    "contact": "张同学",
    "startTime": "2026-10-29T14:00:00",
    "endTime": "2026-10-29T16:00:00",
    "status": "PENDING",
    "createdAt": "2026-10-28T09:00:00"
  }
]
```

- `roomId`、`date` 均可选，同时传取交集。
- 建议按开始时间倒序。

### 3.5 强制取消预约（管理员）

`PUT /api/admin/bookings/{id}/cancel`（仅 `ADMIN`）

```json
// 请求
{ "reason": "场地临时维修" }
// 成功 data: AdminBookingVO（status=CANCELLED，含 cancelReason/cancelledBy/cancelledAt）
```

- `reason` 必填，长度 ≤ 200；为空返回 `400 +「请填写取消原因」`。
- 可取消 `PENDING / ONGOING / FINISHED`（用于处理已结束的异常预约），已取消返回 `400`。
- 成功必须写一条 `FORCE_CANCEL` 操作日志。

### 3.6 会议室管理（管理员）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/rooms` | 返回 `RoomVO[]`（含停用） |
| POST | `/api/admin/rooms` | 新增，返回新 `RoomVO` |
| PUT | `/api/admin/rooms/{id}` | 修改，返回更新后 `RoomVO` |
| DELETE | `/api/admin/rooms/{id}` | 删除，成功 `data: null` |

请求体：

```json
{ "name": "E2E临时会议室", "location": "E2E楼1层", "capacity": 10, "equipment": "投影仪，白板", "status": "AVAILABLE" }
```

- 名称/位置/容量必填；名称不可重复；容量为正整数。
- `equipment` 允许字符串或数组，后端统一存数组。
- **删除时存在未取消预约 → `409 +「该会议室存在有效预约，请先处理预约」`（FR-03）**，前端在弹窗内展示，不关闭弹窗。
- 新增/修改/删除均写操作日志。

### 3.7 用户管理（管理员）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/users` | 返回 `AdminUserVO[]`（含 `createdAt`） |
| POST | `/api/admin/users` | 创建账号，返回新用户 |
| PUT | `/api/admin/users/{id}` | 修改姓名/部门/角色/状态 |

创建请求：

```json
{ "username": "e2e_user_01", "name": "E2E测试用户", "department": "测试部", "role": "USER", "password": "******" }
```

- 账号 3–20 位字母/数字/下划线且唯一；密码 ≥ 6 位。
- 修改请求字段均可选：`{ "name", "department", "role", "status" }`。
- 停用账号后该用户已有令牌失效。
- 不允许停用当前登录账号、不允许修改当前登录账号的角色。
- 新增写 `CREATE_USER`；状态/信息变更写 `UPDATE_USER`；角色变化写 `ROLE_CHANGE`。

### 3.8 操作日志（管理员）

`GET /api/admin/logs`（仅 `ADMIN`，普通用户 `403`）

```json
// data: OperationLogVO[]（按时间倒序）
[
  {
    "id": 7,
    "operatorId": 3,
    "operatorUsername": "admin001",
    "operatorName": "王管理员",
    "operationType": "FORCE_CANCEL",
    "targetType": "BOOKING",
    "targetId": 4,
    "summary": "强制取消预约 MR202610270004（原因：场地临时维修）",
    "beforeData": { "id": 4, "status": "FINISHED" },
    "afterData": { "id": 4, "status": "CANCELLED" },
    "createdAt": "2026-10-28T16:20:00"
  }
]
```

枚举：

- `operationType`: `CREATE_USER | UPDATE_USER | ROLE_CHANGE | CREATE_ROOM | UPDATE_ROOM | DELETE_ROOM | FORCE_CANCEL`
- `targetType`: `USER | ROOM | BOOKING`

前端只读展示，不提供删除/修改入口。

### 3.9 利用率概览

`GET /api/admin/stats/utilization` **本周未实现**（FR-20“有时间”项），前端也没有对应页面，不伪造数据。

## 4. 前端对后端的硬性假设

1. **状态以 `status` 字段为准**，前端不按本地时间推导；否则浏览器时间不准会导致四态展示错误。
2. **30 分钟限制必须由后端最终校验**，前端按钮禁用只是体验优化。
3. **冲突 409 的 `data.occupiedSlots` 必须返回**，否则页面只能显示一句笼统提示，达不到 FR-10。
4. **删除会议室 409 的 message 必须是中文业务提示**，前端会原样展示。
5. **操作日志与业务操作同事务**：操作成功后日志必须存在；操作失败不能留下“已发生”的脏日志。
6. **时间不带时区后缀**，前端按本地时间解析；如果后端改成 UTC/ISO，需要先改本文与 `utils/datetime.ts`。

## 5. mock 与正式后端的差异

| 项 | mock-server | 正式后端（组员实现） |
|----|-------------|----------------------|
| 存储 | 进程内存，重启重置 | MySQL |
| 密码 | scrypt（Node 原生） | BCrypt |
| 令牌 | 内存 Map，30 分钟 | 持久化/可撤销的 Session Token |
| 冲突并发 | 单进程顺序处理 | 事务 + `meeting_room` 行锁 |
| 编号 | 自增主键派生 `MRyyyyMMddNNNN` | 同口径，需保证并发唯一 |
| 日志 | 与操作同函数同步写 | 与业务同事务写 |

mock 只服务前端联调与自测，不代表正式后端已通过并发/安全验收。
