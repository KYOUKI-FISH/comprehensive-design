## BUG-11-01 依赖版本漂移，安装结果与《技术栈清单》不一致

| 字段 | 内容 |
|------|------|
| **来源** | 第 10 周技术栈对齐时发现，原记录见 `docs/week10/技术栈对齐说明.md`；本周按要求原样搬入 Bug 日志第 1 条 |
| **类型** | 依赖/构建 |
| **现象** | `frontend/package.json` 最初写 `^3.4.38`、`^2.7.8`，`npm install` 实际解析为 **Vue 3.5.44、Element Plus 2.14.7、vue-router 4.6.4、vue-tsc 2.2.12**，与《技术栈清单（第六周）》要求的 Vue 3.4.x / Element Plus 2.7.x 不符。页面未立刻报错，属于“能跑但版本不正确”的隐性偏差。 |
| **复现步骤** | 1. 清空 `frontend/node_modules` 与 `package-lock.json`；2. 在 `frontend` 执行 `npm install`；3. 执行 `npm ls vue element-plus vite typescript`；4. 观察到 Vue 3.5.x、Element Plus 2.14.x。 |
| **定位到哪** | `frontend/package.json` 的依赖版本范围；npm 的 semver 解析把 `^3.4.38` 升到了 3.5.x。 |
| **怎么修的** | 把依赖全部改成**精确版本**（去掉 `^`/`~`）：`vue 3.4.38`、`element-plus 2.7.8`、`vite 5.4.21`、`typescript 5.4.5`、`vue-tsc 2.0.29`、`@vitejs/plugin-vue 5.1.4`、`vue-router 4.4.5`；重新生成 `package-lock.json`。 |
| **回归结果** | `npm ls` 确认上述精确版本；`npm run typecheck`、`npm run build` 通过；第 10 周 smoke 86/86、E2E 63/63 通过；第 11 周复跑仍通过。 |
| **当前状态** | **已关闭** |

## BUG-11-03 375px 下列表表格被压成逐字换行，操作列不可读

| 字段 | 内容 |
|------|------|
| **来源** | 第 11 周 TC-09 首轮 375×667 适配检查 |
| **类型** | 适配/可用性 |
| **现象** | 375px 宽度下，会议室列表 7 列被强行压进 375px：名称、位置、设备等列逐字换行（如“学术报告厅”竖排成 5 行），操作列被挤到右侧且难以点击；虽然页面没有横向溢出，但内容不可读，移动端实际不可用。 |
| **复现步骤** | 1. Edge 打开 `/rooms`；2. 开发者工具切换 375×667（或 Playwright 移动视口）；3. 观察列表表格：列宽被压缩、文字逐字换行、操作列与内容重叠/挤出。 |
| **定位到哪** | `frontend/src/styles/main.css` 的 `.table` 只有 `width: 100%`，没有最小宽度；外层 `.table-wrap` 已有 `overflow-x: auto`，但没有内容可滚动。 |
| **怎么修的** | 给 `.table` 增加 `min-width: 720px;`，让表格在 `.table-wrap` 内横向滚动，页面本身仍保持视口宽度。不改表格结构、不改列顺序、不影响桌面布局。 |
| **回归结果** | 375×667 重新测量：列表/详情 `documentScrollWidth` 均为 375；表格列宽恢复可读，不再逐字换行；表格内部可横向滚动，“进详情”可点击并进入详情；1366×768、768×1024 无回归；E2E 63/63 通过。截图见 `docs/week11/适配截图/Edge_375x667_列表.png`。 |
| **当前状态** | **已关闭** |
