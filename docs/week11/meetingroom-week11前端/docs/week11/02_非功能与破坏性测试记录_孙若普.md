## 3. 越权取消

### 3.1 请求

```http
DELETE /api/bookings/3 HTTP/1.1
Host: localhost:8080
Authorization: Bearer 7d749783…（user002 令牌，已脱敏）
Accept: application/json
```

- 目标预约：id=3，编号 `MR202610300003`，主题“师生座谈”，归属 user001。
- 攻击者：user002。user002 与 user001 都是普通用户，角色相同、权限相同，唯一差别是预约归属。

### 3.2 响应

```http
HTTP/1.1 403 Forbidden
Content-Type: application/json; charset=utf-8

{"code":40305,"message":"无权操作他人的预约","data":null}
```

### 3.3 库内数据

| 时点 | id | 编号 | 主题 | 状态 | cancelledAt |
|------|----|------|------|------|-------------|
| 操作前 | 3 | MR202610300003 | 师生座谈 | PENDING | 空 |
| 操作后 | 3 | MR202610300003 | 师生座谈 | PENDING | 空 |

结论：越权取消被 403 拦截，预约没有被取消，状态与取消字段均未变化。

## 5. 时间边界

### 5.1 构造基线

- 学术报告厅（roomId=1）明天 2026-10-29 已有 10:00–11:00 的预约（user002）。
- “首尾相接”用该时段的结束时间 11:00 作为新预约开始，提交 11:00–12:00；按半开区间 `[start, end)` 应放行。
- 三条非法时段选在 6 号楼研讨室（roomId=5），避免与种子数据冲突，确保“拒绝”不是被冲突检测误判。

### 5.2 四条请求与结果

| 边界 | 提交时段 | 会议室 | 预期 | 实际响应 | 库内条数 |
|------|----------|--------|------|----------|----------|
| 跨天 | 2026-10-29 23:00 — 2026-10-30 01:00 | 6号楼研讨室 | 400，不跨天 | **400**，`code=40024`，`单次预约不能跨天` | 0 |
| 超 8 小时 | 2026-10-30 08:00 — 17:00（9 小时） | 6号楼研讨室 | 400，不超过 8 小时 | **400**，`code=40025`，`单次预约不能超过 8 小时` | 0 |
| 结束早于开始 | 2026-10-30 14:00 — 13:00 | 6号楼研讨室 | 400，结束必须晚于开始 | **400**，`code=40023`，`结束时间必须晚于开始时间` | 0 |
| **首尾相接** | 2026-10-29 11:00 — 12:00 | 学术报告厅 | **成功**（半开区间） | **200**，`code=0`，`预约成功`，编号 `MR202610290005` | **1** |

### 5.3 库内数据

| 项 | 提交前 | 提交后 | 差值 |
|----|--------|--------|------|
| user001 我的预约 | 2 条 | 3 条 | +1（仅首尾相接那条） |
| 管理端预约总数 | 4 条 | 5 条 | +1 |
| 非法三条命中数 | — | 0 条 | 0 |

结论：跨天、超 8 小时、结束早于开始三条均未落库；首尾相接按 `start_new < end_old AND end_new > start_old` 判定为不冲突，成功落库 1 条。这条用例同时证明后端没有把 `<` 写成 `<=`。

## 6. 复跑指南（正式后端合并后）

脚本已支持 `WEEK11_BASE_URL`，但**只允许本机地址**：

```bash
# 1. 启动组内正式后端（Spring Boot + MySQL），确认 8080 可访问
# 2. 提供测试账号口令（不要写进仓库、不要贴到截图）
export WEEK11_USER_PASSWORD='<user001/user002 的测试口令>'
export WEEK11_ADMIN_PASSWORD='<admin001 的测试口令>'

# 3. 复跑（脚本会拒绝非 localhost 地址）
WEEK11_BASE_URL=http://localhost:8080 npm run test:week11:api
```

正式后端复跑时，把“库内数据”的接口回读换成 SQL：

```sql
-- 越权取消：操作前后各执行一次
SELECT id, reservation_no, status, cancelled_at
FROM reservation
WHERE id = ?;

-- 越权查看：管理数据条数
SELECT COUNT(*) FROM reservation;
SELECT COUNT(*) FROM operation_log;

-- 时间边界：四条提交的落库结果
SELECT id, subject, start_time, end_time, status
FROM reservation
WHERE subject LIKE 'W11-时间边界-%';
```

判定口径不变：越权取消 403 且预约不变；越权查看 403 且不泄露数据；时间边界前三条 400、首尾相接 200 且只落一条。
