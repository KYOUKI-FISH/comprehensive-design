4. 控制台无脚本错误；预期业务错误（400/401/403/409 资源错误）不计入。
5. `requestfailed` 事件 0 条（过滤导航取消产生的 `net::ERR_ABORTED`），即没有加载失败的网络请求。

### 2.1 375px 下表格的说明

修复前（BUG-11-03）：表格没有最小宽度，7 列被压进 375px，名称/位置逐字换行，操作列挤在一起，截图可读性很差。

修复后：`.table { min-width: 720px; }`，表格在 `.table-wrap`（`overflow-x: auto`）内横向滚动。效果是：

- **页面本身不横向溢出**（documentScrollWidth=375）；
- 表格列宽保持可读，不再逐字换行；
- 操作列需要在表格内部横向滑动后点击（Playwright 会自动滚动到元素并点击，实测可进入详情）。

这是第 11 周允许的“修 bug”，不是界面美化；完整的移动端卡片式布局留到第 12 周。

## 4. Chrome 分支：未执行，原因如实写

- 本机没有 Chrome。检测路径：
  - `C:/Program Files/Google/Chrome/Application/chrome.exe`
  - `C:/Program Files (x86)/Google/Chrome/Application/chrome.exe`
  - `%LOCALAPPDATA%/Google/Chrome/Application/chrome.exe`
- 三个路径均不存在，脚本把 Chrome 标记为 `available: false`，没有伪造“Chrome 通过”。
- 按计划 §5 卡点 7 的写法：**仅 Edge 实测，Chrome 待补**。
- 补测方式：安装 Chrome 后重新执行 `npm run test:week11:compat`；脚本会自动检测并跑同一套视口与全流程，结果写入 `compat-result.json` 的 `browsers` 数组，不需要改代码。

> Edge 与 Chrome 同为 Chromium 内核，但兼容性结论不能互相替代。本文只对 Edge 156 负责。
