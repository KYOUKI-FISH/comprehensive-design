## 一、接口签名

统一返回 `ApiResponse<T>`：包含code、message、data；T是data的类型。数组统一用 `类型[]` 表达。以下是简化方法声明，HTTP方法和路径写在注释中，不包含业务实现或完整Spring注解。

```java
// 1. 登录：POST /api/auth/login
ApiResponse<LoginResponse> login(LoginRequest request);

// 2. 登出：POST /api/auth/logout；令牌从Authorization请求头取
ApiResponse<Void> logout();

// 3. 会议室列表：GET /api/rooms；四项均为可选查询条件
ApiResponse<RoomVO[]> listRooms(
    String location, Integer minCapacity, String status, String date
);

// 4. 占用时段：GET /api/rooms/{id}/occupancy（有时间）
// id为路径参数，date为必填查询参数
ApiResponse<OccupancyResult> occupancy(Long id, String date);

// 5. 提交预约：POST /api/bookings；request为请求体
ApiResponse<CreateBookingResult> submitRequest(CreateBookingRequest request);

// 6. 我的预约：GET /api/bookings/mine
ApiResponse<ReservationVO[]> getBookResult();

// 7. 修改预约：PUT /api/bookings/{id}
// id为路径参数，request为请求体
ApiResponse<ReservationVO> changeReserve(Long id, ChangeBookingRequest request);

// 8. 取消预约：DELETE /api/bookings/{id}；保留预约记录
ApiResponse<Void> cancelMyReserve(Long id);

// 9. 全部预约：GET /api/admin/bookings；五项均为可选查询条件
ApiResponse<ReservationVO[]> allReserve(
    Long userId, Long roomId, String status, String startDate, String endDate
);

// 10. 强制取消：PUT /api/admin/bookings/{id}/cancel
// id为路径参数，request为请求体
ApiResponse<ReservationVO> forceCancelRequest(Long id, ForceCancelRequest request);

// 11a. 会议室管理——查询：GET /api/admin/rooms；查询条件可选
ApiResponse<RoomVO[]> listAdminRooms(String status, String location);

// 11b. 会议室管理——新增：POST /api/admin/rooms
ApiResponse<RoomVO> createRoom(CreateRoomRequest request);

// 11c. 会议室管理——修改：PUT /api/admin/rooms/{id}
// 请求类型的完整字段待主笔补清
ApiResponse<RoomVO> updateRoom(Long id, UpdateRoomRequest request);

// 11d. 会议室管理——删除：DELETE /api/admin/rooms/{id}

// 12a. 用户管理——查询：GET /api/admin/users；查询条件可选
ApiResponse<UserVO[]> listUsers(String status, String role);

// 12b. 用户管理——新增：POST /api/admin/users
ApiResponse<UserVO> createUser(CreateUserRequest request);

// 12c. 用户管理——修改：PUT /api/admin/users/{id}
ApiResponse<UserVO> updateUser(Long id, UpdateUserRequest request);

// 13. 日志查询：GET /api/admin/logs；查询条件可选
// operator暂按文本表达，具体含义和类型仍需草案明确
ApiResponse<OperationLogVO[]> listLogs(
    String operator, String actionType, String startTime, String endTime
);

// 14. 利用率概览：GET /api/admin/stats/utilization（有时间）
ApiResponse<UtilizationVO[]> getUtilization(String startDate, String endDate);
```

这仍是14个接口编号，其中#11、#12分别展开4种和3种方法。#4、#14保持“有时间”优先级。

### 签名中各类型装什么

`ApiResponse`、`LoginRequest`、`LoginResponse`、`RoomVO`已有代码定义。下表中其余请求类型名，以及OccupancyResult、CreateBookingResult、UtilizationVO是示例暂拟名；ReservationVO、UserVO、OperationLogVO是草案使用的名称，不能把名称出现当成类型已完整实现。

| 类型 | 字段说明 |
|---|---|
| LoginRequest | username、password，必填字符串 |
| LoginResponse | userId、username、realName、role |
| RoomVO | id、name、location、capacity、equipment、status、occupiedSlots；当前代码equipment为字符串，occupiedSlots为字符串数组 |
| OccupancyResult | roomId、roomName、date、occupiedSlots；每个时段含startTime、endTime |
| CreateBookingRequest | roomId、date、startTime、endTime、topic、attendeeCount、contact、purpose；仅purpose选填 |
| CreateBookingResult | id、reservationNo、status（PENDING） |
| ReservationVO | id、reservationNo、roomId、roomName、startTime、endTime、topic、attendeeCount、contact、status；#9额外要求预约人姓名，字段名待补 |
| ChangeBookingRequest | roomId、startTime、endTime、topic、attendeeCount、contact，均选填 |
| ForceCancelRequest | cancelReason，必填字符串 |
| CreateRoomRequest | name、location、capacity，及选填的equipment、remark |
| UpdateRoomRequest | 草案只写“可改字段”，目前仅明确status可用于启停；完整字段待补 |
| CreateUserRequest | username、realName、password，及选填的phone |
| UpdateUserRequest | status、realName、phone，均选填 |
| UserVO | 草案未展开完整字段，只明确不能含password；待补 |
| OperationLogVO | id、operatorId、operatorUsername、actionType、targetType、targetId、beforeData、afterData、createdAt；部分字段的结构、类型待补 |
| UtilizationVO | roomId、roomName、bookingCount、bookedHours |

类型有定义或字段说明，签名才不是只列一个空名字。上表未明确的部分如实保留待补状态。

## 二、3个前端调用示例

统一使用项目的 `request<T>`：它已配置/api前缀，检查业务code，并直接返回业务data。调用结果不用再写 `.data`。实际放进前端工程时，先导入：

```ts
import { request } from '@/api/http'
import type { RoomVO } from '@/types/api'
```

下面的代码放在 `async` 函数中执行。登录后的接口还需按后续明确的鉴权约定携带令牌；当前示例是文档推演，不是已完成联调。

### 1. 查询会议室：GET＋查询参数

```ts
const rooms = await request<RoomVO[]>({
  url: '/rooms',
  method: 'get',
  params: {
    minCapacity: 8,
    status: 'ENABLED'
  }
})
```

含义：查找已启用、至少容纳8人的会议室。成功后rooms就是会议室数组；空数组显示“未找到符合条件的会议室”。失败在列表区域显示提示。

### 2. 提交预约：POST＋请求体

本示例的返回类型按草案定义：

```ts
interface CreateBookingResult {
  id: number
  reservationNo: string
  status: 'PENDING'
}

const booking = await request<CreateBookingResult>({
  url: '/bookings',
  method: 'post',
  data: {
    roomId: 1,
    date: '2026-10-27',
    startTime: '2026-10-27 09:00:00',
    endTime: '2026-10-27 10:00:00',
    topic: '课程讨论',
    attendeeCount: 6,
    contact: '示例联系人',
    purpose: '讨论课程任务'
  }
})
```

含义：提交预约，成功后用booking.reservationNo读取预约编号。失败时显示原因，并保留表单；发生冲突时还需显示被占用时段。

日期字段采用01草案的date；时间值采用前端调用栏给出的完整日期时间格式。两端字段名、时间格式仍需统一确认。示例编号和数据不表示真实数据库中已有记录。

### 3. 修改预约：PUT＋路径编号＋请求体

本示例按01草案暂拟一条预约的TS类型，供调用说明使用；时间格式及字段可空性仍需主笔补清。

```ts
interface ReservationVO {
  id: number
  reservationNo: string
  roomId: number
  roomName: string
  startTime: string
  endTime: string
  topic: string
  attendeeCount: number
  contact: string
  status: 'PENDING' | 'ONGOING' | 'FINISHED' | 'CANCELLED'
}

const updatedBooking = await request<ReservationVO>({
  url: '/bookings/101',
  method: 'put',
  data: {
    roomId: 2,
    topic: '修改后的会议主题'
  }
})
```

含义：修改编号101的预约，将会议室改为2，同时修改主题。成功后用updatedBooking更新页面；失败保留修改内容并显示原因。当前调用采用01允许修改roomId的口径，不能据此认为前端调用栏已同步。

### 共用的失败处理写法

任一请求可放进下面的结构。errorMessage表示页面绑定的提示文本；实际提示位置按对应页面设置。

```ts
let errorMessage = ''

try {
  // 在这里执行上面的一条请求，并处理成功结果。
} catch (error) {
  errorMessage = error instanceof Error ? error.message : '请求失败，请重试'
}
```

`try/catch`在这里只示范文字提示。当前request工具把失败转换为Error(message)，没有保留冲突响应的结构化数据；再加上草案未给清occupiedSlots元素结构，所以预约冲突时段的完整解析仍待补清，不能写成已实现。
