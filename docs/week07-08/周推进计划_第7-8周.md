#### 2.2.1 实体与关系（本组口径）

| 实体 | 主键 | 关键属性 | 关系 |
|------|------|----------|------|
| 用户 `user` | `id` | `username`（唯一）、`password`（BCrypt 摘要）、`real_name`、`role`（USER／ADMIN，**枚举列，不单独建 role 表**）、`phone`、`status`（ACTIVE／DISABLED） | 1 : N 预约（`user.id` → `reservation.user_id`） |
| 会议室 `meeting_room` | `id` | `name`、`building`、`room_no`、`capacity`、`equipment`、`status`（ENABLED／DISABLED）、`purpose` | 1 : N 预约（`meeting_room.id` → `reservation.room_id`） |
| 预约 `reservation` | `id` | `reservation_no`（唯一）、`user_id`、`room_id`、`reserve_date`、`start_time`、`end_time`、`topic`、`attendee_count`、`contact`、`purpose`、`status`（PENDING／ONGOING／FINISHED／CANCELLED）、`cancel_reason`、`created_at`、`updated_at` | 承载全部业务关系 |

> **角色为何不单独建表**：本组只有 USER／ADMIN 两种固定角色，需求清单 FR-02 只要求"按角色区分权限"，无角色管理功能（角色管理不在 FR-01～FR-20 内）→ 以枚举列承载，符合"需求清单里没有的功能不要画进设计"这条硬要求。**不建 `role` 表，也不建 `booking` 之外的关联表**。

#### 2.2.2 状态取值口径（与任务书示例不一致处，以需求清单为准）

| 表.字段 | 取值 | 依据 |
|---------|------|------|

| 11 | 预约编号 | `reservation_no VARCHAR(32)` 唯一，生成规则写进注释（如 `MR` + yyyyMMdd + 3 位序号，形如 `MR20261012001`；**实现写进第 9 周**） | FR-07 |
| 12 | 取消原因 | `cancel_reason VARCHAR(200) DEFAULT NULL`，管理员强制取消时必填（FR-16） | FR-16 |

#### 4.2.2 脚本执行顺序（干净库一次跑通）

```
1. CREATE DATABASE IF NOT EXISTS meeting_room (utf8mb4)   -- 可重复执行
2. USE meeting_room;
3. DROP TABLE IF EXISTS ...（按外键依赖倒序：operation_log → reservation → meeting_room → user）
4. CREATE TABLE user             （含 UNIQUE / CHECK / COMMENT）
5. CREATE TABLE meeting_room     （含 UNIQUE(building,room_no) / CHECK / COMMENT）
6. CREATE TABLE reservation      （含 FK ×2 均 RESTRICT / CHECK / 复合索引）
7. CREATE TABLE operation_log    （含 FK → user(id) / 索引）
8. INSERT 初始化数据：
   8.1 user            —— 1 管理员 + 1 普通用户（BCrypt 摘要）
   8.2 meeting_room    —— 3 间（含 1 间 DISABLED）
   8.3 reservation     —— 1 组重叠（冲突）+ 1 组首尾相接（不冲突），覆盖 status 的 `PENDING` 与 `CANCELLED`
   8.4 operation_log   —— 1 条示例
9. 收尾校验 SELECT（条数自查，脚本末尾打印，不含口令与哈希）
```

**验证命令（李牧远执行，README 同步）**：

```bash
# 干净库一次跑通
mysql -u root -p --mysqlx=0 < docs/week07-08/schema.sql
# 三个关键自查
# ① 冲突组：重叠两条 → 应判冲突；首尾相接两条 → 不应判冲突
# ② 删会议室：DELETE FROM meeting_room WHERE id=<有预约的那间> → 应被 RESTRICT 拒绝
# ③ 状态取值：SELECT DISTINCT status FROM reservation → 只出现已列清的取值
```

#### 4.2.3 第 8 周"三问"验收自答（写进文档，课上直接用）

| 问 | 答 |
|---|---|
| 每条预约的开始／结束时间怎么存？ | `reservation.start_time`／`end_time`，类型 `DATETIME NOT NULL`；占用区间为半开区间 `[start_time, end_time)`；另存 `reserve_date DATE NOT NULL` 便于按日查询与聚合 |
