## 2. 快速启动（三步，每步一条命令）

在 `meetingroom-week10/` 目录下依次执行：

```bash
# 第 1 步：安装前端依赖（root 依赖仅跑自测脚本时才需要）
npm run setup

# 第 2 步：启动本地 mock 后端（默认 8080，数据仅存内存）
npm run dev:mock

# 第 3 步：另开一个终端，启动前端（默认 5173）
npm run dev:web
```

浏览器打开 `http://localhost:5173`。

> 想一条命令同时起前后端可执行 `npm run dev`（内部仍是 mock + Vite 两个进程）。
> 需要跑冒烟/E2E 时，先执行一次 `npm install` 安装根目录的 `playwright-core`。

## 3. 页面与路由（V1.0）

| 路由 | 页面 | 可访问角色 | 说明 |
|------|------|-----------|------|
| `/login` | 登录页 | 未登录 | 账号/口令登录；账号不存在与口令错误使用同一句提示，防账号枚举；无注册/忘记密码入口 |
| `/rooms` | 会议室列表 | 普通用户、管理员 | 按名称/最小容量/位置筛选；显示可预约/已停用；“进详情” |
| `/rooms/:id` | 会议室详情 | 普通用户、管理员 | 基本信息复用列表接口（D1）；按日期查已占用/空闲时段；普通用户可“去预约” |
| `/bookings/new` | 提交预约 | 普通用户 | 行内校验；冲突时展示被占用时段并保留已填内容 |
| `/bookings/mine` | **我的预约** | 普通用户 | 四态展示（待开始/进行中/已结束/已取消）；距开始超过 30 分钟可修改/取消；取消后提示时段释放 |
| `/admin/bookings` | **全部预约处理** | 管理员 | 按会议室/日期筛选；强制取消必须填写原因；成功后提示日志已记录 |
| `/admin/rooms` | **会议室管理** | 管理员 | 新增/编辑/启停/删除；存在有效预约时删除返回 409 中文提示 |
| `/admin/users` | **用户管理** | 管理员 | 创建账号、修改姓名/部门/角色、启停账号；当前登录账号角色与状态不可改 |
| `/admin/logs` | **操作日志** | 管理员 | 只读，展示操作人/时间/类型/对象/摘要/变更前后数据 |
| `/403` | 无权访问 | 已登录 | 角色不匹配时跳转 |

角色规则与需求清单/角色说明一致：

- 普通用户菜单：会议室查询、我的预约；**不渲染**任何管理入口。
- 管理员菜单：会议室查询 + 全部预约处理、会议室管理、用户管理、操作日志；**不渲染“我的预约”**（角色说明的权限矩阵中管理员没有个人预约入口，管理员处理预约走“全部预约处理”）。
- 管理员不能提交个人预约：前端路由把 `/bookings/new`、`/bookings/mine` 限制为 `USER`，详情页不显示预约按钮；mock 后端也会对管理员返回 403。前端隐藏不是安全边界，后端校验才是。

## 4. 现场验收路径

### 4.1 普通用户八步

| 步 | 操作 | 页面/接口结果 |
|----|------|---------------|
| 1 | user001 登录 | 进入会议室列表，菜单只有“会议室查询 / 我的预约” |
| 2 | 按名称或容量筛一次 | 结果条数与内容对得上（如 `301` → 3号楼301） |
| 3 | 进学术报告厅详情，选“明天” | 看到种子占用 10:00–11:00 与其余空闲时段 |
| 4 | 去预约，提交 11:00–12:00 | 成功并给出 `MRyyyyMMddNNNN` 预约号 |
| 5 | 再提交 10:30–11:30 | 失败提示“该时段已被占用”，并列出 10:00–11:00；已填内容保留 |
| 6 | 打开“我的预约” | 看到第 4 步那条，状态“待开始”（PENDING），有修改/取消按钮 |
| 7 | 修改为 12:00–13:00 | 保存成功，列表时间跟着变 |
| 8 | 取消这条，回到会议室详情 | 状态变“已取消”；12:00–13:00 重新出现在空闲时段 |

### 4.2 管理员四步

| 步 | 操作 | 页面/接口结果 |
|----|------|---------------|
| 1 | admin001 登录 | 菜单与普通用户明显不同，含四个管理入口 |
| 2 | 全部预约处理，按会议室 + 日期筛一次 | 结果条数与内容对得上（如 3号楼301 + 明天 → 课题组周会） |
| 3 | 强制取消“已结束的学术研讨会” | 不填原因 → 前端拒绝并提示“请填写取消原因。”；填写后成功 |
| 4 | 打开操作日志 | 可查到强制取消、新增/修改/删除会议室、新增/修改用户、角色变更共 7 条记录，字段完整，可展开变更前后 JSON |

### 4.3 30 分钟口径

修改与取消按钮只对“待开始且距开始超过 30 分钟”的预约展示；不足 30 分钟时按钮禁用并提示，后端还会再校验一次（FR-12／FR-13）。演示时请挑明天的预约，不要挑当天已开始的记录。

## 5. 关键实现说明

### 5.1 状态四态由后端驱动

`PENDING / ONGOING / FINISHED / CANCELLED` 全部由后端按当前时间与取消标记推导后返回，前端只负责展示，不自行计算状态。这样“进行中”“已结束”不会因为浏览器时间不准而漂移。

### 5.2 修改/取消的 30 分钟与冲突

- 前端 `minutesUntilStart()` 只用于提前禁用按钮，最终由后端 `checkOperable()` 校验。
- 修改后由后端重新检测冲突，仍使用半开区间：`start_new < end_old && end_new > start_old`，首尾相接不冲突。
- 冲突时后端返回 `409 + data.occupiedSlots`，页面展示具体被占用时段，并保留已填内容（FR-18）。

### 5.3 操作日志（NF-14）

以下敏感操作会写日志，页面可查、普通用户不可查看、界面不提供删除：

| 操作 | 日志类型 |
|------|----------|
| 新增用户 | `CREATE_USER` |
| 修改姓名/部门/状态 | `UPDATE_USER` |
| 修改角色 | `ROLE_CHANGE` |
| 新增/修改/删除会议室 | `CREATE_ROOM` / `UPDATE_ROOM` / `DELETE_ROOM` |
| 强制取消预约 | `FORCE_CANCEL` |

每条日志包含操作人账号/姓名、操作时间、操作类型、对象类型与 ID、摘要、变更前数据、变更后数据。

### 5.4 删除会议室的 409（FR-03）

会议室管理页删除前由后端检查是否存在未取消预约：

- 存在 → `409「该会议室存在有效预约，请先处理预约」`，弹窗保持打开并展示中文原因；
- 不存在 → 删除成功并写 `DELETE_ROOM` 日志。

### 5.5 前端错误提示统一（NF-10）

新增 `frontend/src/utils/errors.ts`：

- 后端返回的中文业务消息优先展示；
- 后端只给技术信息或 HTTP 码时，按状态码映射为中文兜底文案；
- 自动过滤 `500`、`TypeError`、`Error:`、堆栈等技术内容。

所有页面（登录、列表、详情、预约、我的预约、四个管理页）统一使用 `toUserMessage()`，不再直接拼接 `error.message`。

### 5.6 mock 后端边界

`mock-server/server.mjs` 实现第 10 周前端联调所需的 9 条接口（我的预约、修改、取消、全部预约、强制取消、会议室管理 4 方法、用户管理、操作日志），数据仅存内存，重启即重置。

它**不冒充正式后端**：数据库、BCrypt、事务行锁、预约编号并发方案、令牌持久化仍由组员按第 8 周设计落地。前端接口字段以 `docs/week10/前端接口假设.md` 为准，正式后端字段不同时优先改 `types/api.ts` 与 `api/*.ts`。

### 5.7 Element Plus 2.7.8 的接入方式

- `frontend/src/main.ts` 全量注册 `ElementPlus`，并固定 `zh-cn` 语言包；
- `frontend/src/styles/main.css` 在组件库样式**之后**引入，用 `--el-color-primary` 等变量把主题色对齐项目主色（`#175cd3`）；
- 页面主操作按钮统一改用 `el-button`，用 `native-type` 保留原生 `submit` 行为，原有 `.btn` 样式类继续负责视觉；
- 表格状态列统一改用 `el-tag`，关闭 `disable-transitions`，避免列表首帧出现 `opacity: 0` 的空白状态；
- 表单控件仍保留原生 `input` / `select`：`datetime-local`、`selectOption` 与现有自动化断言依赖原生控件，没有为了“用组件库”强行替换成 `el-date-picker` / `el-select` 而牺牲可测试性。

## 9. 已知限制与合并注意事项

1. **mock 不是正式后端**：数据在内存，重启即重置；令牌也在内存，重启后旧令牌失效。
2. **接口字段以 `docs/week10/前端接口假设.md` 为准**：如果组仓库后端字段名/枚举值不同，优先改 `types/api.ts` 与 `api/*.ts`，不要把兼容代码散落到页面。
3. **前端路由守卫不是安全边界**：普通用户直接调管理接口必须由后端返回 403（NF-03）。mock 已按此实现，正式后端必须同样校验。
4. **操作日志必须与业务操作同事务**：mock 是单进程同步写，正式后端需按 NF-14 保证“操作成功日志必在、操作失败不写脏日志”。
5. **管理员菜单不含“我的预约”**：按角色说明的权限矩阵做的取舍；若组内决定调整，先改角色说明/需求清单，再改 `RoleMenu.vue` 与路由。
6. **演示口令随机生成**：截图与仓库中没有明文口令；需要固定口令时用环境变量注入，口令文件不要提交。
7. **不要把 mock-server 当成组仓库正式后端提交**；如组内同意入库，请标注“仅本地联调”。
