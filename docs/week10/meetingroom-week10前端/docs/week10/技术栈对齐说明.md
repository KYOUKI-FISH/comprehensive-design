## 2. Element Plus 2.7.8 的实际使用位置

| 位置 | 用法 |
|------|------|
| `frontend/src/main.ts` | `app.use(ElementPlus, { locale: zhCn })`，固定中文语言包 |
| `frontend/src/styles/main.css` | 覆盖 `--el-color-primary` 等主题变量，主色对齐项目 `#175cd3`；组件库 CSS 先引入，项目 CSS 后引入 |
| 登录页 | 登录按钮 `el-button`（`native-type="submit"`） |
| 会议室列表 / 详情 | 筛选按钮、重试按钮、时段预约按钮 `el-button`；会议室状态 `el-tag` |
| 预约表单 | 提交按钮、重试按钮、再预约按钮 `el-button`；成功状态 `el-tag` |
| 我的预约 | 刷新、重试、修改、取消、保存、返回 `el-button`；预约四态 `el-tag` |
| 全部预约处理 | 查询、重置、刷新、强制取消、返回 `el-button`；预约四态 `el-tag` |
| 会议室管理 | 刷新、新增、编辑、删除、保存、返回 `el-button`；会议室状态 `el-tag` |
| 用户管理 | 刷新、新增、编辑、保存、返回 `el-button`；用户状态 `el-tag` |
| 操作日志 | 刷新、重试 `el-button` |
| `RoleMenu.vue` | 退出登录 `el-button` |

**没有替换的部分**：表单输入框、日期时间控件和下拉框保留原生 `input` / `select`。原因有两条：

1. `datetime-local` 原生控件能直接承载 `YYYY-MM-DDTHH:mm`，与后端时间格式、表单校验逻辑一致；
2. 现有 86 项 API 冒烟与 63 项端到端断言依赖 `#id` 直接填值与 `selectOption`，换成 `el-date-picker` / `el-select` 会牺牲可测试性，收益只是外观。

这是有意识的取舍，不是“装了组件库但没用”。

## 5. 合并到组仓库时的注意事项

1. 不要把 `node_modules/` 复制进组仓库；合并后执行一次 `npm install`。
2. `frontend/package-lock.json` 应与 `package.json` 一起提交，保证组员装到同一组版本。
3. 若组仓库已有自己的 Element Plus 主题配置，以组仓库为准，只保留本目录的组件用法，不覆盖组内主题。
4. 正式后端接入后，`VITE_PROXY_TARGET` 指向组后端地址；mock 仅保留为离线联调备用。
