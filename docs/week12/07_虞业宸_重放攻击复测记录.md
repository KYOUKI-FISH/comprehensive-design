## 1. 结论先说

| 项 | 结果 | 判据 |
|---|---|---|
| R-1 重放提交预约（同一 body ×5） | **200×1 ＋ 409×4** | 仅 1 条落库，编号不重复 |
| R-2 重放取消预约（DELETE ×3） | **200 ＋ 400×2**（“该预约已取消，无需再取消”） | 状态仍 CANCELLED，不新增行、无 5xx |
| R-3 重放已吊销令牌（登出后原样重放） | **401 ＋ 401** | 令牌不可重放，库无新增 |
| R-4 重放管理端停用账号（PUT ×2） | **200 ＋ 200**（幂等） | 无 5xx，账号状态一致，两次动作均留痕 |
| HTTP 状态行与 body.code 一致性 | **全部一致** | 逐条相等 |
| 数据恢复 | **26 → 26** | 与基线一致 |

**一句话口径**：重放同一份合法写请求 5 次，只成功 1 次、其余 4 次被冲突判定明确拒绝；重复取消被状态机拒绝；吊销令牌重放两次均 401；管理端重复动作幂等且照常审计留痕——**重放不会带来额外业务副作用**。

## 3. 用例明细

### R-1 重放写请求：POST /api/bookings ×5

同一令牌、同一 URL、**字节级相同的 body**（脚本先 `json.dumps` 成 bytes，五次原样发出，不重新序列化）：

| 重放次序 | HTTP | body.code | 耗时 | 返回 |
|---|---|---|---|---|
| #1 | **200** | 200 | 150.5 ms | 创建成功（PENDING） |
| #2 | **409** | 409 | 44.7 ms | 该会议室在此时间段已被占用 |
| #3 | **409** | 409 | 40.6 ms | 同上 |
| #4 | **409** | 409 | 33.3 ms | 同上 |
| #5 | **409** | 409 | 31.7 ms | 同上 |

库内核对：该室该日**有效预约 1 条**，编号去重数 / 行数 = **1 / 1**。
说明：第 2—5 次落地在冲突判定上——半开区间判定式把“与自己完全重叠”判为冲突，因此重放不具备落库能力。

### R-2 重放取消：DELETE /api/bookings/{id} ×3

| 重放次序 | HTTP | body.code | 消息 |
|---|---|---|---|
| #1 | **200** | 200 | ok |
| #2 | **400** | 400 | 该预约已取消，无需再取消 |
| #3 | **400** | 400 | 同上 |

库内状态仍为 `CANCELLED`；无 5xx；取消是**状态迁移**，重复请求被状态机拒绝，不产生二次释放或二次审计。

### R-3 重放已吊销令牌

`user2` 登录取得令牌 → 调用 `POST /api/auth/logout` 吊销 → 原样重放：

| 重放内容 | HTTP | 结果 |
|---|---|---|
| `GET /api/bookings/mine`（原令牌） | **401** | 未登录或登录已过期 |
| `POST /api/bookings`（原 body、原令牌） | **401** | 同上 |

库内该主题记录仍为 1 条（即 R-1 那条），吊销令牌没有写入任何数据（对应 NF-04）。

### R-4 重放管理端停用账号：PUT /api/admin/users/2 ×2

| 重放次序 | HTTP | body.code |
|---|---|---|
| #1 `{"status":"DISABLED"}` | **200** | 200 |
| #2 同一 body | **200** | 200（幂等） |
| 恢复 `{"status":"ACTIVE"}` | **200** | 200 |

操作日志条数 **8 → 11**（两次停用 + 一次启用各留一条），账号最终状态 `ACTIVE`，全程无 5xx。
说明：管理端重复动作**不拒绝**但幂等——坏状态不会出现，审计链不断（NF-14）。

## 4. 边界必须如实说（被追问时的原话）

> V1.0 **没有 nonce／时间戳窗口**这类通用防重放机制，也没打算假装有。我们防的是“重放造成业务副作用”：
> ① 写请求被业务规则幂等化——冲突判定、状态机、唯一编号、归属校验；
> ② 令牌吊销后立即失效，重放无效；
> ③ 无副作用的 GET 重放不拦截（重放读请求不构成风险）。
> 若后续接入外部系统或支付类动作，才需要补 nonce／签名／时间戳窗口，这属于 V2.0 的安全增强，不在本期交付内。

## 5. 与 PPT 口径的衔接

PPT 第 9 页「安全攻击防御」现写“SQL 注入、越权访问、XSS 及重放攻击均阻断”。本记录把**重放**一项补齐后的可辩护措辞：

- 建议卡片描述改为：**「SQL 注入、越权访问、XSS 与重放均无副作用」**（比“阻断”准确：R-4 是幂等而非拒绝）；
- 若坚持用“阻断”，至少要说清口径：“**写请求重放被业务规则拦下或幂等化，不产生重复数据**”。
- 现场被要求演示时，30 秒可跑 R-1：连发 5 次同一 body，屏幕上是 1 个 200 + 4 个 409，查库 1 条。
