## 2. 三个关键设计决策（课堂/预答辩会被问）

### 2.1 冲突判定式只写一处，而且写在纯函数里

```
冲突 ⟺ start_new < end_old  AND  end_new > start_old        （严格不等号）
```

- 实现位置：`BookingTimeRules.conflicts(...)`，Service、409 载荷共用同一份"当日已占用时段"查询结果。
- **为什么不用 `<=`**：09:00-10:00 与 10:00-11:00 首尾相接，10:00 这一刻前一单已结束、后一单才开始，用 `<=` 会把正常的相邻预约全判成冲突。
- **为什么抽成纯函数**：判定式能在不连数据库的情况下被用例逐条压，包括"只重叠 1 秒"和"首尾相接"这类边界。

### 2.2 先锁会议室行，再查冲突

`BookingService.create` 整体 `@Transactional`，第一步执行 `SELECT ... FROM meeting_room WHERE id = ? FOR UPDATE`。

- 不锁的话：两个用户同时订同一间会议室，双方都查到"无冲突"然后双双插入——典型幻读，超订就发生了（NF-07）。
- 锁的粒度选**会议室行**而不是全表：不同会议室之间互不影响，并发度够用。

### 2.3 预约不写操作日志表

分工表里"`operation_log` 写入"指的是**提供日志写入能力**（`OperationLogService`），而不是让提交预约去写日志。

- 依据：`ck_log_operation_type` 只认 9 种**管理员敏感操作**，`BOOKING_CREATE` 不在其中，硬写会被数据库 CHECK 拒绝（ERROR 3819）；
- 预约本身已在 `reservation` 表留痕，重复记一遍会让日志表混进业务流水，与第 8 周 §2.4 定稿口径冲突。

## 6. 交接口径（给孙若普、李牧远，务必先看这段）

1. **业务失败是 HTTP 200**，靠 `code` 判断：`200` 成功、`400` 参数、`401` 未登录、`403` 越权、`404` 不存在、**`409` 冲突**。前端不要在 `catch` 里等 409，要判 `res.code`。
2. **409 的 `data.occupiedSlots`** 形如 `[{"startTime":"10:00","endTime":"11:00"}]`（只给时分），前端直接拼"10:00-11:00 已被占用"。这也正是 `http.ts` 必须挂 `data` 字段的原因——否则前端拿不到这段。
3. **时间入参容错**：`2026-10-28 09:00:00`、`2026-10-28T09:00`、`09:00`（配 `date`）三种都能收，字段名请用 `startTime`／`endTime`（不是 `start`／`end`）。
4. **身份识别（临时）**：令牌模块尚未合入，当前用请求头 `X-User-Id: <userId>` 走过渡通道；组长的拦截器落地后会在 `request.setAttribute("userId", ...)` 处生效，**本模块无需改动**。令牌合入后这个过渡头应删除（它不是安全边界）。
5. **演练请选未来时段**：FR-08 规定开始时间不得早于当前时间，用"今天上午"做演示会被 400，提示语是"开始时间不能早于当前时间，请选择未来的时段"。
