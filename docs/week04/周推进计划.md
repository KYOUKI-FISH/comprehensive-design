## 2. 本周目标

**总目标**：把第 3 周选定的方案 A（自由时间段预约）落成角色、用例和需求清单，并保证每条需求都能回答"谁用 → 做什么 → 系统怎样反馈"。

具体目标：

1. **补第 3 周欠账**：打 `week03-final` 标签（签字表、责任人栏、文件清单已于 2026-09-23 课前补齐；标签已于 2026-09-30 创建、2026-10-11 核实推送）。
2. **角色说明定稿**：2 个角色（普通用户／管理员），各自写清角色描述、允许的操作、**不允许的操作**（含理由）、前置／后置条件、业务规则、数据权限；输出角色权限矩阵。
3. **用例视图**：1 张用例图（含 2 个角色、10 个用例、include／extend 关系）+ 10 条用例清单（每条含前置、主流程、异常、后置）。
4. **功能需求清单 V1**：20 条功能需求，完整覆盖第 3 周"本学期必须实现"12 项，每条标注优先级与来源。
5. **非功能需求**：6 条，每条写明验证方式；另列 3 条"质量与交付要求"承接第 10–12 项必须实现。
6. **需求来源可追溯**：建立"第 2 周问题／场景 → 用例 → 需求"的映射表，保证 P01–P03 与 3 个场景每条都有去向。
7. **过程可追溯**：全组 5 人本周均有 Git 提交；材料统一归档至 `docs/week04/`。

**本周不做的**：不写代码、不画界面原型、不做数据流图（第 5 周内容）、不引入"暂不实现"清单中的任何功能。
